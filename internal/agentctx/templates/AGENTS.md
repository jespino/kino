# Kino project

This folder is a **Kino** animation project. You are the agent running in a
terminal inside Kino Studio. Next to this terminal the user sees a live
preview and a timeline of the project's `.kino` script ({{FILE}}).

## How editing works

- The whole animation lives in **`{{FILE}}`**, written in the Kino DSL. Read
  `.kino/docs/DSL.md` (the language reference) and
  `.claude/skills/kino/SKILL.md` (workflow, house style, pitfalls) before
  your first edit.
- Edit `{{FILE}}` directly. Kino Studio reloads it on every save and
  recompiles: valid versions show up in the preview and the timeline at once.
- Assets (images for the `image` widget, voice-cloning recordings) live in
  this folder. Reference them with paths relative to this folder.
- The commands in the skill (`npm run check`, `npm run render`, ...) only
  exist inside the Kino source repository. In this project, use the status
  file below instead.

## Checking your work

After every save, Kino Studio writes **`.kino/status.json`**:

```json
{
  "file": "{{FILE}}",
  "sha256": "9f2c…",
  "ok": false,
  "error": { "line": 12, "col": 3, "message": "unknown widget 'arr'" },
  "duration": 21700,
  "steps": [{ "kind": "step", "name": "grow", "start": 14600, "end": 18500, "line": 70 }],
  "narration": { "clips": 4, "missing": 1 }
}
```

`sha256` is the hash of the text that was compiled: compare it with
`sha256sum {{FILE}}` and wait (a second or two) until it matches what you
saved before trusting `ok`. Times are in milliseconds. If the status file is
missing, Kino Studio isn't open on this project.

A moment after a successful compile, Kino Studio also draws
**`.kino/sheet.png`**: every page of the deck (the end of every step and
`then` sub-step) in one picture, each labeled with its number, step name and
line. Once it's written, `status.json` gets `"sheet": ".kino/sheet.png"`, and
then the picture shows the same `sha256`. Open it to check your layout:
overlaps, things off screen, text too small, empty areas.

## Working rules

1. Read `{{FILE}}` before editing; keep the user's names, comments and style.
2. Make focused edits, then check `.kino/status.json` and fix every error.
   Look at `.kino/sheet.png` after bigger changes.
3. Times need units (`500ms`, `2s`). Positions are in video pixels.
4. Narration (`say`) is generated by the local TTS server when the user plays
   or exports; you don't need to run it.
5. Do not delete assets unless the user asks.
